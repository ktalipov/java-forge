# Проекты

Мини-проекты закрепляют теорию: в них видно, умеешь ли ты собрать из знаний рабочую программу.

Каждый проект это отдельный Maven-модуль в `projects/<имя>/` со своим README, кодом и тестами.

Новый проект: `./scripts/new-project.sh tasks-cli "CLI task manager"`

## План проектов

| Проект | Когда начинать | Что закрепляет | Статус |
|--------|----------------|----------------|--------|
| `tasks-cli`: менеджер задач в консоли | после модуля 06 `streams` | коллекции, streams, файлы, тесты | ⬜ |
| `rest-api`: REST API с базой данных | после модуля 14 `spring` | Spring Boot, PostgreSQL, миграции, интеграционные тесты | ⬜ |
| свободный проект | после любого | то, что хочется довести до релиза | ⬜ |

## Как вести проект

1. Создай модуль скриптом и заполни в его README цель и требования.
2. Заведи в GitHub Milestone `project: <имя>`, а каждую фичу оформи как issue.
3. Одна фича = ветка `project/<имя>-<фича>` = один PR. Коммиты: `project(<имя>): <что сделано>`.
4. Код без тестов в `main` не попадает.
5. Закончил: заполни «Что я узнал» в README, поставь тег `<имя>-v1.0.0` и создай GitHub Release.

Подробности в [docs/WORKFLOW.md](../docs/WORKFLOW.md#проекты).
