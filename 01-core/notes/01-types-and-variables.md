# Types and variables

- **Модуль:** 01-core
- **Статус:** ✅ закончен

## Зачем это нужно

Переменные позволяют хранить и использовать данные. Тип определяет, какие значения может представлять переменная и какие операции над ними допустимы.

## Суть

### Переменные

**Переменная** — именованная сущность, через которую программа обращается к значению определённого типа.
```java
int age = 20;
age = 21;
```
Значение `age` изменилось с `20` на `21`. Тип переменной при этом остаётся `int`.

### Виды переменных

- **Instance variables (поля экземпляра)** — принадлежат объекту; у разных объектов могут быть разные значения.
- **Class variables (поля класса)** — объявляются с `static`; одна переменная связана с классом и общая для его экземпляров.
- **Local variables (локальные переменные)** — объявляются внутри метода, конструктора или блока и доступны в соответствующей области видимости.
- **Parameters (параметры)** — переменные, получающие значения при вызове метода или конструктора.

### Типы данных

Java — статически типизированный язык: тип выражения и переменной проверяется компилятором.

Типы делятся на две группы:

- **Примитивные:** `byte`, `short`, `int`, `long`, `float`, `double`, `char`, `boolean`.
- **Ссылочные:** классы, интерфейсы, массивы, перечисления и другие ссылочные типы. Например, `String`.

| Тип       | Размер                      | Диапазон / значения                                                                                                  | Значение по умолчанию |
| --------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------- |
| `byte`    | 8 бит                       | −128 … 127                                                                                                           | `0`                   |
| `short`   | 16 бит                      | −32 768 … 32 767                                                                                                     | `0`                   |
| `int`     | 32 бита                     | −2³¹ … 2³¹ − 1                                                                                                       | `0`                   |
| `long`    | 64 бита                     | −2⁶³ … 2⁶³ − 1. Для обозначения литерала типа `long` используется суффикс `L`.                                       | `0L`                  |
| `float`   | 32 бита                     | Приблизительно 6–7 значащих десятичных цифр. Для обозначения литерала типа `float` используется суффикс `f` или `F`. | `0.0f`                |
| `double`  | 64 бита                     | Тип дробных литералов по умолчанию. Приблизительно 15–16 значащих десятичных цифр                                    | `0.0`                 |
| `char`    | 16 бит                      | беззнаковая кодовая единица UTF-16                                                                                   | `'\u0000'`            |
| `boolean` | Не фиксирован спецификацией | `true` или `false`                                                                                                   | `false`               |

#### Важное уточнение
Значения по умолчанию относятся к полям экземпляра и статическим полям. Локальные переменные не получают значения по умолчанию автоматически — перед чтением им необходимо явно присвоить значение.

```java
public class DefaultValues {
    int age;                  // 0
    double price;             // 0.0
    boolean isActive;         // false
    char grade;               // '\u0000'

    public void printValues() {
        int number;
        // System.out.println(number); // Ошибка компиляции
    }
}
```
В этом примере поля получают значения по умолчанию, а локальная переменная `number` не может быть прочитана до явного присваивания.

### Именование переменных

- Имена чувствительны к регистру: `age` и `Age` — разные имена.
- Имя может содержать буквы Unicode, цифры, `$` и `_`, но не может начинаться с цифры.
- Пробелы запрещены; ключевые слова Java нельзя использовать в качестве имён переменных.
- Для переменных рекомендуется выбирать понятные имена и придерживаться стиля `lowerCamelCase`: `currentSpeed`.
- Константы обычно именуются в стиле `UPPER_SNAKE_CASE`: `MAX_SPEED`.

### `float` и `double`

`float` и `double` представляют числа с плавающей точкой по стандарту IEEE 754. Значение кодируется знаком, экспонентой и значащей частью.

| Характеристика                                    | `float`          | `double`         |
| ------------------------------------------------- | ---------------- | ---------------- |
| Размер                                            | 32 бита          | 64 бита          |
| Бит знака                                         | 1                | 1                |
| Экспонента                                        | 8 бит            | 11 бит           |
| Дробная часть                                     | 23 бита          | 52 бита          |
| Точность значащей части для нормализованных чисел | 24 двоичных бита | 53 двоичных бита |
| Пример литерала                                   | `7.5f`           | `7.5`            |

Для нормализованного конечного числа значение вычисляется по формуле:

$$
(-1)^s \times 1.f \times 2^{e-\text{Bias}}
$$

- `s` — бит знака.
- `f` — дробная часть значащей части.
- `e` — сохранённая экспонента.
- `Bias` — смещение экспоненты: `127` для `float`, `1023` для `double`.
- Скрытая единица перед дробной частью не хранится явно.

Для нулей, субнормальных чисел, бесконечностей и `NaN` используются специальные представления.

### Дополнительный код (Two's Complement)

Типы `byte`, `short`, `int` и `long` представляют целые числа со знаком в дополнительном коде.

Для получения дополнительного кода отрицательного числа в фиксированной разрядности выполняются следующие действия:

1. Записывается модуль числа в двоичном виде.
2. Все биты инвертируются.
3. К результату прибавляется `1`.

Пример для `-5` в 8 битах:
```
+5          0000 0101
Инверсия    1111 1010
+1          1111 1011
```
Дополнительный код обеспечивает единое представление нуля и позволяет выполнять сложение чисел со знаком с помощью общей двоичной арифметики.

## Пример

```java
public class TypesAndVariables {
    public static void main(String[] args) {
        int age = 20;
        long population = 7_000_000_000L;

        float temperature = 18.5f;
        double price = 19.99;

        char grade = 'A';
        boolean isActive = true;
        String name = "Alex";

        System.out.println(name);
        System.out.println(age);
        System.out.println(price);

        double result = 0.1 + 0.2;
        System.out.println(result); // 0.30000000000000004
    }
}
```

Тип переменной нельзя изменить после объявления:
```java
int number = 5;
// number = "Hello"; // Ошибка компиляции
```

## Как это устроено внутри

### Stack и Heap

- **Stack (стек)** хранит кадры вызовов методов и обычно локальные переменные.
- **Heap (куча)** используется для размещения объектов и массивов.

Упрощённая модель:

|Элемент|Типичное размещение|
|---|---|
|Локальная примитивная переменная|В кадре метода; обычно стек|
|Примитивное поле объекта|Внутри объекта в куче|
|Локальная ссылочная переменная|В кадре метода; обычно стек|
|Ссылочное поле объекта|Внутри объекта в куче|
|Объект или массив|Куча|

Ссылочная переменная хранит ссылочное значение, которое может указывать на объект или быть `null`. Сам объект не является значением этой переменной. Это модель для понимания: JVM может оптимизировать размещение данных, поэтому физическое расположение не всегда буквально соответствует таблице.

### Числа с плавающей точкой

Некоторые десятичные дроби, например `0.1` и `0.2`, не имеют точного конечного представления в двоичной системе. Поэтому вычисления с `float` и `double` могут давать небольшую погрешность.

### Переполнение целых чисел

У целочисленных типов фиксированный диапазон. Например, при переполнении `int`
результат обычной целочисленной арифметики может перейти к отрицательному
значению. Для представления больших значений применяется подходящий тип, например `long`, если его диапазона достаточно, или `BigInteger`.

### Типичные ошибки

- **Сравнение вычисленных значений double с помощью ==.** В подходящих задачах сравнивается абсолютная разница между значениями с допустимой погрешностью (epsilon). Её величина зависит от масштаба чисел и требований задачи.
```java
double a = 0.1 + 0.2;
double b = 0.3;
double epsilon = 1e-9;

System.out.println(Math.abs(a - b) < epsilon);
```
- **Игнорирование переполнения int** при вычислении больших сумм и факториалов. При достаточном диапазоне применяется long, в противном случае — BigInteger.
- **Сравнение String и объектов-обёрток, например Integer, с помощью ==.** Для сравнения строк по содержимому применяется equals(). Для сравнения значений Integer также обычно используется equals(), поскольку == сравнивает ссылки, а не гарантированно сами значения.
- **Ожидание дробного результата при делении целых чисел.** Выражение 1 / 2 даёт 0, поскольку оба операнда имеют целочисленный тип. Для получения дробного результата используется 1.0 / 2 либо один из операндов преобразуется к double.
- **Отсутствие суффикса f у литерала float.** Например, корректная запись выглядит следующим образом: float value = 7.5f;.
- **Применение float или double для точных денежных расчётов.** Для таких расчётов используется BigDecimal; значения рекомендуется создавать из строк, например new BigDecimal("19.99").
- **Предположение о том, что все переменные физически хранятся строго в стеке или куче.** Такое представление является упрощённой моделью: оптимизации JVM могут влиять на фактическое размещение данных.

## Вопросы для самопроверки

1. Почему `Integer.MAX_VALUE + 1` отрицательное и как узнать об этом на этапе выполнения?
> [!question]- Мой ответ
> Целые числа в Java хранятся в дополнительном коде. При переполнении значение «заворачивается» через границу диапазона.
>
Обычные целочисленные операции не выбрасывают исключение при переполнении. Метод `Math.addExact()` выбрасывает `ArithmeticException`, если результат сложения выходит за допустимый диапазон типа.

2. Чему равно `(byte) 200` и почему?
> [!question]- Мой ответ
> 
> **Ответ: −56.**
> 
> В Java тип `byte` занимает 8 бит и хранит значения в диапазоне от −128 до 127. Число `200` выходит за пределы этого диапазона, поэтому при явном приведении `(byte) 200` сохраняются младшие 8 бит числа.
> 
> 1. Переводим число `200` в двоичную систему счисления:
>     
>     `200₁₀ = 11001000₂`
>     
> 2. Старший бит равен `1`, следовательно, полученный 8-битный шаблон представляет отрицательное число в дополнительном коде.
>     
> 3. Инвертируем все биты:
>     
>     `11001000 → 00110111`
>     
> 4. Прибавляем `1`:
>     
>     `00110111 + 1 = 00111000`
>     
> 5. Переводим результат в десятичную систему счисления:
>     
>     `00111000₂ = 56₁₀`
>     
>     Следовательно, исходное число равно `−56`.
>     
> 
> **Итог:** `(byte) 200 == -56`.

3. Почему `Integer a = 127, b = 127;` даёт `a == b` истину, а для 128 ложь?
> [!question]- Мой ответ
> Оператор `==` при сравнении двух объектов `Integer` сравнивает ссылки на объекты, а не их числовые значения.
>
> В классе `Integer` реализовано кэширование объектов для значений от `-128` до `127` включительно. При автоупаковке (*autoboxing*) значение типа `int` преобразуется в `Integer`.
>
> - **Для `127`:** значение входит в диапазон кэширования, поэтому обе переменные ссылаются на один и тот же объект. В результате `a == b` возвращает `true`.
> - **Для `128`:** значение выходит за пределы стандартного диапазона кэширования, поэтому при обычной автоупаковке создаются разные объекты. В результате `a == b` возвращает `false`.
>
> **Вывод:** для сравнения числовых значений объектов `Integer` следует использовать метод `equals()`, а не оператор `==`.

3. Если Java передаёт всё по значению, как метод меняет содержимое массива?
 > [!question]- Мой ответ
>
> Java передаёт по значению копию ссылки на массив, а не сам массив. Копия ссылки указывает на тот же объект, поэтому метод может изменить его содержимое.
